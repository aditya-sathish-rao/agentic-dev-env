Sandbox the crew: a Linux VM for computation, the Mac for authority

Every claim below was checked against this tree and this machine today; the commands that produced them are named. Nothing here is implemented yet.

The one-sentence answer

Move the crewmates into a Lima Linux VM: herdr panes inside the guest, one shared worktree root as the only host path they can see, one proxied egress path, and an ephemeral credential minted per task. The Mac keeps the first mate, the vault, the allowlist, the token broker and the repo the pins are authoritative in.

The cost, stated up front: the first mate still runs as you, with your network and your hardened gh token. The boundary covers the processes that execute untrusted repo content. Closing the first mate too is shape A in section 2, and it is a later, separable move because phases 1 and 2 are identical for both.

1 · Where the agents run today

What worktrees already buy

Two crewmates never fight over a branch or an index. That is git-state isolation and it works; nothing here changes it, and the same treehouse pool moves inside the new boundary.

What they do not buy

A worktree is a directory on your disk. The process in it still reads your keys, your other repos and the network. The gap is blast radius, not branches.

The four claims the plan must close

The trigger is not a malicious crewmate. It is a prompt injection in a README, an issue body, a test fixture or a dependency's output, executed inside a tool loop that already has all four.

3 · Decision A: which runtime

The unit of isolation decides the answer. A fleet needs a kernel boundary, an enforceable egress policy, and a server the host can attach to. A per-task job needs none of that.

Option Boundary Egress control Human attach Fleet state Cost here Verdict
Lima 2.1.3
nixpkgs · vz driver		 full Linux kernel VM nftables, default deny ssh → herdr --remote persistent disk 8 GiB resident, ~10 GiB disk fleet
Apple container 1.7.1 one microVM per container no first-class allowlist exec only, no ssh container lifetime ~1 s start, nothing idle per task
Colima / Docker Desktop Linux VM host firewall still needed ssh possible VM Daemon, licensing, not declarative no
macOS sandbox-exec none: same kernel, same uid per-operation, not per-host n/a host cheap to write, cannot be trusted no

Recommended: Lima now, Apple container later

Lima gives what a persistent fleet needs and nothing it does not: a real kernel to put nftables in, sshd so herdr --remote works, a disk that survives a reboot, and one nixpkgs-pinned binary. Apple's container is better at the job it is for - a fresh kernel per task - and becomes phase 6, where no human attaches and nothing persists.

Rejected, with reasons

sandbox-exec is a policy language over the same kernel, with no per-hostname network control; it is a speed bump, not a boundary. Docker Desktop or Colima adds a daemon and a licence to get a worse VM than Lima, and neither is a flake input.

4 · Decision B: crewmates only, and what that costs

Chosen: the first mate stays on the Mac; crewmates, their panes and their worktrees run in the VM. The naive version of that is blocked upstream, by firstmate's own contract:

Firstmate does not support placing an individual worker remotely or failing a remote route over to a local replacement. ~/firstmate/docs/remote-secondmates.md

The reason is concrete: the herdr backend selects a local client, and treehouse returns host directories whose absolute paths firstmate then reads and writes. So "crewmates only" needs three pieces, each a seam this repo already knows how to build.

1 · Pane targeting

Every firstmate → herdr call must land on the guest's server. herdr --machine <label> <cmd> already exists, so the seam is a PATH shim in ~/.local/bin — the same trick as the pi wrapper — with a knob in the fork's bin/backends/herdr.sh if the shim cannot cover every call.

2 · One shared path

firstmate reads the worktree it dispatched, so the treehouse pool root is the single host path mounted into the guest — at the same absolute path, so no translation exists anywhere, and $HOME stays outside.

3 · Spawn-time credentials

A pane's pi no longer has av. The guest wrapper receives the ephemeral model key and the task token from the host at spawn, and holds them only for its own lifetime.

What this buys

Untrusted repo content executes in a kernel that cannot see $HOME, cannot reach the vault, cannot open a socket the allowlist does not name, and holds no credential that outlives its task. The worktree it may corrupt is the one it owns.

What it does not buy

The first mate still runs as you, with your network and your hardened gh token, and still reads untrusted issue text. A first-mate compromise has today's blast radius. Shape A is the same work plus moving firstmate in, and it stays available as a later step.

The first card is a spike, not an estimate: if the shim covers every adapter call it is days; if it does not, the fork grows a transport knob and the estimate moves with it.

5 · The six phases, each with a gate

Each phase ends in a state that can be checked by a script, and the check is the same script every later phase re-runs. Nothing advances on a green agent report.

Baseline: write the gap down

½ day

From inside a crewmate pane today, record what is reachable: ls ~/.ssh, gh auth status, curl to a random host, av list. This is the oracle, not a deliverable.

Gate: the transcript exists and every later phase is checked against it.

1

The box: a VM with no way in and one way out

1–2 days

nix/crew-sandbox/lima.yaml (vz, 6 cpu, 8 GiB, sparse 30 GiB, mounts: [] — the pool root is the one mount phase 3 adds — no port forwards, no agent forwarding), crew up|down|status, nftables default-deny, the host proxy.

Gate: uname is Linux · ls /Users fails · mount shows no virtiofs or 9p · curl https://example.com fails · the proxy port answers · DNS resolves.

2

The toolchain: same pins, different OS

2–3 days

Nix inside the guest, then one home-manager module - nix/crew-sandbox/guest.nix - importing tools.nix, crew-tools.nix, the pi package and herdr. Herdr gets a pin of its own: the two release builders currently hardcode kunchenguid/<name>.

Gate: every tool resolves under /nix/store · pi --version equals the host's · a clone through the proxy works · nix-store --verify is clean.

3

Panes move; the first mate does not

2–3 days

The herdr target shim, the pool root mounted at its own absolute path, and the guest's credential handoff at spawn. Firstmate stays where it is; only the pane server and the worker process move.

Gate: a dispatched task's pane runs in the guest while ps on the host shows no worker pi · firstmate reads and writes the worktree without noticing the mount · the pane is visible from the host with live agent state · reconnect works after a guest reboot.

4

Authority: tokens out, broker in

3–5 days

A GitHub App on the host mints an installation token per task (one repo, contents + pull_requests, 60 min). The model key becomes per-task. av, the ssh key and ~/.config/gh are simply absent from the guest.

Gate: a token pushes to its repo and is refused on any other · it reads no org secret · it expires · ssh -T git@github.com fails · killing the proxy stops model traffic.

5

Adversarial proof

1 day

A red-team script run as a crewmate, simulating a prompt injection: read /Users, dump env, POST elsewhere, push to main, push to another repo, reach host services on 192.168.5.2. Six attempts, six recorded failures.

Gate: all six fail with evidence, and the evidence is what the ADR cites.

6

Optional: a microVM per untrusted task

later

Apple container with an image built from the same pins, used by no-mistakes verification and by review of untrusted PRs. Fresh kernel, nothing persists, no human attaches. This is where the runtime in Decision A earns its keep a second time.

Two weeks of work end to end. Phases 1–3 are reversible: delete the VM and the host is exactly as it is today, because nothing host-side moved.

8 · The numbers

8 of 16 GiB

firstmate plus two to four Node agents at ~300 MB each, with build headroom. The Mac keeps 8.

30 GiB sparse

2 base + ~5 nix store + ~3 repos. Only what is written is allocated; the cap is the guard.

3–8 s cold

vz boot to ssh. crew up on a live VM answers in under half a second.

<1 ms

loopback CONNECT per request. Model payloads dominate; the proxy is noise.

Deliberately unchanged

  • identity.nix - the guest has its own user; the host identity is not shared
  • the host's link table, tools.nix, the eight pinned tools
  • update.sh stays host-only; the guest may rewrite its copy and gains nothing
  • the pi-only harness, the vault policy, the 14-day pin gate

Migration, not a flag day

Phases 1–2 leave the host working exactly as now. Phase 3's switch is the herdr shim, which is one file to delete; nothing gains a host credential it did not already have until phase 4, and the old path stays documented until the adversarial check passes.

10 · Decisions

Two are settled and the plan is written around them. Two are open, and neither blocks phases 1–3.

DecisionStateWhat it changes
Which agents move decided crewmates only section 4: a herdr target shim, one mounted pool root, broker-supplied credentials
Where the model key lives decided ephemeral, per task handed to the pane at spawn and never written; proxy-side injection stays a later option
GitHub authority open App installation tokens (one repo, 60 min) or a fine-grained PAT. Phase 4 is the first thing that needs the answer.
macOS-only work open whether Swift tasks are crew work at all. Nothing in phases 1–3 depends on it.

Also fixed: Lima as the runtime, and an Ubuntu LTS guest plus Nix rather than a NixOS image, because generating a Linux image needs a Linux builder this Mac does not have. The declarative surface is unaffected either way: it is the home-manager module.

What this plan does not claim

  • It does not stop a scoped token from opening a malicious PR in its one repo. Review is the control there.
  • It does not sandbox your own shell or editor. Your session is the authority by design.
  • It does not make model traffic private from the provider; that is a provider property, not a boundary here.
  • It does not remove the need for av scan; the host keeps its findings either way.
